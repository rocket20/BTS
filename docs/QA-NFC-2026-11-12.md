# BTS Studio — Checklist de pruebas (12 noviembre 2026)

**Objetivo:** validar la experiencia completa antes de entregar mini paneles a clientes. Usar solo datos ficticios.

## Entorno
- Dashboard BTS: https://www.btsstudio.net/admin/accesos/
- Mini panel: https://www.btsstudio.net/negocios/
- Tarjeta digital: URL emitida en el CSV privado de BTS.
- Crear una empresa de ensayo; comenzar con **3 tarjetas**, no 30. No utilizar datos ni compras reales.
- Mantener el CSV privado de códigos NFC solo dentro de BTS. No compartirlo con la empresa.
- El control físico de grabación/verificación/entrega está en **una rama de desarrollo, no publicado**.

## Alta y autenticación
- [ ] BTS crea empresa nueva y genera usuario/contraseña sin invitar a Supabase.
- [ ] URL empresarial abre el negocio correcto; claves incorrectas no permiten entrar.
- [ ] Cuenta sin empresa asignada no ve información.
- [ ] Usuario de empresa A no ve clientes, programas ni lotes de empresa B.

## Emisión y seguridad
- [ ] BTS genera exactamente 3 códigos distintos y descarga 3 URLs.
- [ ] Mini panel muestra solo referencias internas, cupos disponibles y asignados.
- [ ] Empresa no puede crear códigos nuevos ni leer URL privada.
- [ ] Manipular peticiones desde navegador no permite acceder a datos ajenos.

## Asignación y fidelización
- [ ] Negocio asigna tarjeta a un nombre y beneficio.
- [ ] No es posible asignar por segunda vez el mismo cupo.
- [ ] NFC abre perfil correcto, luego cambia el progreso al acreditar una compra.
- [ ] Repetir la misma referencia de compra es rechazado.
- [ ] Seis compras alcanzan meta y canje reinicia el contador manteniendo historial.

## Roles, finanzas y tarjeta física
- [ ] Staff no puede crear ni asignar tarjetas; solo rol autorizado registra compras.
- [ ] Viewer no puede modificar tarjetas, puntos ni programas.
- [ ] Empresas no tienen acceso al ERP ni a finanzas BTS.
- [ ] iPhone y Android leen correctamente el chip NFC programado.
- [ ] Confirmar que un chip URL estándar puede copiarse: no anunciar tecnología anticopia.

## Control físico — rama pendiente
- [ ] Generada → Grabada → Verificada → Entregada.
- [ ] El negocio no puede asignar antes de que BTS registre entrega.
- [ ] Una verificación fallida retorna a grabación con motivo obligatorio.
- [ ] Historial registra usuario, tarjeta y fecha.

## Cómo reportar errores
Registrar pantalla, usuario/rol, pasos, esperado, observado, captura y severidad (bloqueante/alta/media/baja).

**Bloqueantes:** aislamiento empresarial, emisión de códigos, asignación o transacciones de fidelización. No entregar al cliente mientras fallen.
